Accessibility statement

The ITSG-33 Compliance Navigator aims to be usable by everyone, including people who use assistive technologies. We target WCAG 2.2 Level AA and EN 301 549 v3.2.1.

Conformance status

Version 1.2.0 is evaluated as conforming to WCAG 2.2 Level AA: 45 criteria supported and 11 not applicable. EN 301 549: chapter 9 supported; 4.2.10 (usage with limited cognition, language or learning) is partially supported; 10 (non-web documents) is not evaluated.

Manual review pending. The user interface has changed since the last attested manual review (2026-10-15). Changed: index.html, css/styles.css, js/app.js. Automated results in this report are current; judgements based on code review or visual inspection must be re-confirmed (npm run a11y:attest).

This is a self-assessment. It has not yet been verified with assistive technology or by an independent auditor; see the expertise and independence statement.

Accessibility features

  • Fully operable with a keyboard. A skip link bypasses the navigation, and focus moves to the page heading after navigation.
  • Works with screen readers through native HTML semantics. Status changes (answer status, analysis results, search counts, confirmations) are announced.
  • Follows your system's dark mode, with a manual toggle. Supports Windows high contrast (forced colours) and reduced motion settings.
  • Reflows to a single column down to 320 CSS px (400% zoom) without horizontal scrolling. Report tables scroll within their own area.
  • No time limits, no flashing content, and confirmation before data is deleted or replaced.

Known limitations

  • The subject matter uses specialized security terminology and acronyms; there is no glossary yet (EN 301 549 4.2.10).
  • Downloaded files (Markdown, CSV, JSON) and printed PDFs have not been evaluated for accessibility.
  • Testing has used Chromium only. Firefox and Safari have not yet been tested.

Compatibility

Designed for current versions of Chrome, Edge, Firefox and Safari with JavaScript enabled. It relies on HTML, CSS, JavaScript and WAI-ARIA.

Feedback

If you find a barrier, please report an accessibility problem. Include the page, what you were trying to do, and the browser and assistive technology you use. Problems that block a task are fixed before the next release.

How this statement is maintained

An automated accessibility suite runs on every commit, and this statement, the VPAT and the test report are recompiled from its results. If a check fails, the build fails and the affected criteria are downgraded. When the user interface changes, the manual review is flagged as pending until a reviewer re-confirms it.
